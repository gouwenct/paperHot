paperHOT 第一版方案选择

三种方案都保持“领域可配置”。差别在于第一版要做到多自动、多重。

A. 手动整理版
paperHOT | 今日热点 | 标签 | 来源
手动填写 JSON / Markdown 条目
生成每日热点列表
生成论文详情页

A. 手动优先的静态站点

最快能做出来。你提供论文或链接，系统负责排版成类似 AIHOT 的卡片列表。

B. 半自动 paperHOT
数据源 -> 抓取 -> 打分 -> 人工复核 -> 发布
arXiv / bioRxiv / HF Papers
RSS / GitHub / 博客
LLM 摘要 + 标签 + 推荐理由
每日 HOT 页面

B. 半自动混合源系统

推荐方案。自动抓取论文源和少量资讯源，生成摘要、标签和推荐理由，但第一版保留人工复核。

C. 全自动生产系统
定时任务 | 抓取器 | 数据库 | LLM | 网站 | 后台
多源采集
去重数据库
热度排序
LLM 任务队列
审核后台
自动部署

C. 全自动生产级流水线

最完整，但第一版偏重：需要定时任务、数据库、登录、后台、失败重试和部署流程。

推荐方向

  • 第一版采用 B，让页面和内容尽快真实可用。
  • 把研究领域、关键词、来源权重都放在配置文件里。
  • 先用审核文件代替复杂后台，降低实现成本。

第一版先不做

  • 登录系统和完整管理后台。
  • 为每个来源单独写很复杂的爬虫。
  • 把显微成像规则写死到核心代码里。
