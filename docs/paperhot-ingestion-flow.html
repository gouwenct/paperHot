PaperHot 论文入库流程

这份说明基于当前仓库代码的只读梳理，描述从前端点击“抓取论文”到后端搜索、过滤、富集、翻译、归档和返回页面的实际路径。

当前结论

点击“今日论文”里的 抓取论文 后，前端不会直接逐个访问论文数据库，而是创建一个后端异步抓取任务。后端根据启用的关键词和信源并行抓取候选论文，然后统一进入一条本地管线：去重、字符串关键词过滤、字符串领域过滤、日期范围筛选、初步排序截断、Crossref 元数据补全、LLM 摘要翻译和推荐理由、EasyScholar 期刊指标、基于 LLM 摘要和期刊指标的最终重评分、写入本地归档。

当前保存的用户配置里，信源开关只有 Google Scholar 是启用状态；Google 搜索、arXiv、bioRxiv、Semantic Scholar 当前关闭。代码本身支持这些信源，如果前端没有传入任何可识别信源，后端会默认使用 arXiv、bioRxiv、Semantic Scholar。

点击之后的主流程

1. 前端收集条件 读取启用关键词、启用信源、起止日期、Google 起始条目。 入口：paperRefreshBody()
2. 创建后端任务 POST 到 /api/papers/refresh/start，后端返回任务 id。 前端随后轮询状态接口。
3. 后端选择模式 当前前端“抓取论文”按钮传的是 mode=recent 加起止日期；today 和 last7 是后端保留模式。
4. 并行抓取信源 arXiv、bioRxiv、Semantic Scholar、Google Scholar、Google 搜索按启用项并发请求。
5. 合并候选池 所有信源结果 flatten 成一个 rawPapers 列表。
6. 漏斗过滤 先去重，再关键词过滤，再领域锚点过滤，再日期范围过滤。
7. 排序和截断 先用字符串规则做初步 score 排序并最多取 80 篇；LLM 和期刊指标出来后会重新计算最终分数。
8. 富集和入库 标题补全、Crossref、LLM、EasyScholar、最终重评分，最后合并到 archive.json 并写缓存和抓取日志。

1. 会去哪些数据库搜索文章？

信源 后端函数 实际请求方式 当前配置状态 时间/分页机制
Google Scholar via SerpApi fetchGoogleScholarPapers() 读取 config/google-scholar.json，使用配置的 endpoint、query 参数、API Key，解析 organic_results。 已启用 支持 maxPages、num、本地 rolling cursor。当前代码未主动加 scisbd，所以排序主要依赖 SerpApi/Scholar 默认结果。
Google 搜索 via SerpApi fetchGoogleSearchPapers() 复用 Google 配置，但强制 engine=google，解析普通网页搜索结果。 当前关闭 支持 SerpApi 分页和 rolling cursor；普通 Google 结果日期不稳定，代码允许无日期网页结果继续进入 Crossref/LLM。
arXiv fetchArxivPapers() 请求 https://export.arxiv.org/api/query。 当前关闭 代码明确设置 sortBy=submittedDate 和 sortOrder=descending，从新到旧拉取。多个关键词在 arXiv 查询里用 OR 组合。
bioRxiv fetchBioRxivPapers() 请求 https://api.biorxiv.org/details/biorxiv/{startDate}/{endDate}/0/json。 当前关闭 按日期区间取回，再本地关键词过滤。
Semantic Scholar fetchSemanticScholarPapers() 请求 https://api.semanticscholar.org/graph/v1/paper/search。 当前关闭 传入 query、limit、fields；多个英文关键词会合并成一个空格分隔的 query，不是逐个关键词循环搜索。如果是时间范围抓取，会在本地按 publicationDate/year 过滤。
Crossref enrichPapersWithCrossref() 不是初始搜索源，而是富集源。按 DOI 或标题补 DOI、期刊、作者、发表日期。 有候选时调用 Google 搜索疑似 DOI 链接会要求标题匹配，避免把错误网页 DOI 写入论文。
EasyScholar enrichPapersWithJournalMetrics() 不是初始搜索源，而是期刊指标富集源。 已启用 对可识别期刊名查询影响因子、分区等，并写入本地期刊指标缓存。

2. 搜索完之后如何处理？

去重

初始候选先进入 dedupePapers()。目前第一轮去重键是 paper.id，没有 id 时用 title-source。后续真正写入归档时，mergePaperLists() 使用更稳定的归档键：优先 DOI，没有 DOI 时使用 id、url 或 title。

注意：跨信源如果 DOI 缺失、标题略有差异，第一轮候选池去重可能不会合并；归档阶段会再按更灵活的 key 合并。

关键词和领域过滤

这两步当前都是字符串规则，不是 LLM。filterPapersByKeywords() 会在标题、摘要、标签、来源中匹配启用关键词。对于 SIM、RIM、PRIM 这类短缩写，代码要求同时出现显微成像相关上下文，避免普通英文缩写误命中。

filterPapersByDomainAnchors() 会再检查显微、成像、重建、illumination、bioimage 等领域锚点，把只碰巧命中关键词但不在当前科研领域内的结果剔除。LLM 不参与这两步过滤，它在后面的摘要翻译、推荐理由和最终重评分阶段参与。

日期筛选

前端页面现在只给用户一个起止日期范围；点击“抓取论文”时，前端把它作为 mode=recent、startDate、endDate 发给后端。也就是说，前端看到的是“日期范围抓取”，后端内部用 recent 模式承接。

today 和 last7 仍存在于后端接口中：today 要求论文发表日期等于当天日期，last7 会用今天往前 6 天的滚动范围。但当前主前端没有给它们单独按钮。普通 Google 网页搜索经常没有结构化日期，代码允许这类无日期网页候选继续进入 Crossref/LLM，最终入库前仍会再做严格日期过滤。

评分和排序

评分现在分两段：第一段 scorePaper() 只用于候选召回后的初步排序和截断，避免把明显无关的结果送进昂贵的 Crossref/LLM/期刊指标流程。它仍然是字符串规则，不能作为最终推荐质量判断。

第二段 rescorePaperAfterEnrichment() 在 LLM 摘要翻译、推荐理由和 EasyScholar 期刊指标之后运行，并覆盖最终 score。期刊权重按影响因子分档：IF 大于 30 为 A 档，IF 10 到 30 为 B 档，IF 0 到 10 为 C 档；预印本、未查询或不清楚的文章默认给平均权重 B 档。

LLM 本身只生成中文摘要 abstractZh 和推荐理由 reason；本地重评分规则会结合英文摘要、中文摘要和推荐理由判断相关性：传统结构光照明显微镜的新理念/新范式给 A 档；传统 SIM 算法或改进给 B 档；深度学习结合 SIM 给 B 档；生物结果中明确和其他方法对比的，会额外加一点分。最终排序再按重评分后的 score 降序，分数相同时按发表日期新到旧。

元数据补全

Google 结果标题如果包含省略号，enrichTruncatedGoogleTitles() 会尝试打开网页，从 HTML meta 或 title 中恢复完整标题。随后 enrichPapersWithCrossref() 用 DOI 或标题查 Crossref，补 DOI、期刊、作者、日期。对于 Google 搜索推断出的 DOI，代码要求 Crossref 标题与原标题相似，否则会移除可疑 DOI 和 URL。

翻译和推荐理由

enrichPapersWithLlmInsights() 读取 config/llm.json。当前 LLM 已启用，模型配置为阿里百炼兼容 OpenAI chat completions 的 qwen-plus。Prompt 要求：英文标题不翻译；abstractZh 严格翻译原始摘要，不扩写、不评价；reason 用 1 到 2 句中文说明推荐理由。

如果历史归档论文缺少 AI 结果，enrichMissingLlmInsights() 会在读取缓存或归档时补跑 LLM，并尽量恢复原始英文摘要，避免把旧的生成式中文摘要当作原摘要继续翻译。

期刊指标和本地入库

LLM 处理后，enrichPapersWithJournalMetrics() 会对非预印本期刊查询 EasyScholar，并复用本地缓存。最后 mergePapersIntoArchive() 把本次论文合并进 data/papers/archive.json。重复论文保留原身份字段，只在有新 LLM 或期刊指标时补充摘要翻译、推荐理由、token 使用和期刊指标。

本地文件输出

文件 用途
data/papers/archive.json 长期论文库。所有抓取成功并入库的论文最终合并到这里。
data/papers/{date}.json 或 data/papers/{date}-recent.json 单次模式缓存。再次非刷新读取时优先使用。
data/papers/fetch-log.json 最近抓取日志，记录各信源返回数量、漏斗计数、候选快照、LLM 用量。
data/papers/google-rolling-cursors.json Google Scholar / Google 搜索滚动分页游标。开启 rollingFetch 后，下次从保存的 start 继续。
data/papers/journal-metrics-cache.json EasyScholar 期刊指标缓存。
