# PaperHot 今日论文视觉优化设计

日期：2026-07-22

## 背景

PaperHot 是本地科研论文工作台，核心价值是帮助用户快速发现、判断和整理论文。当前前端已经覆盖抓取任务、筛选、论文卡片、阅读状态、失败恢复和配置等复杂流程，但不同区域的颜色、字重、卡片、标签和状态表达尚未形成统一系统，标题、摘要、指标与操作也容易同时争夺注意力。

本设计只定义后续优化方向和验收边界，不修改运行时代码。首要场景是“今日论文”快速扫描与决策，视觉改造幅度为中度重塑：保留现有功能、数据和接口语义，允许明显调整页面层级、卡片结构、筛选控制和导航表现。

## 目标

- 让用户按“抓取状态 -> 标题与推荐理由 -> 关键指标 -> 收藏或标星”的稳定路径扫描页面。
- 建立浅色、暗色共用的视觉令牌和状态语法，消除多套颜色、字重、圆角与阴影并存的问题。
- 保持科研工作台所需的信息密度，不把页面改造成营销落地页或杂志式大留白页面。
- 保持桌面高频操作效率，并为移动端提供同等清晰的导航和筛选路径。
- 只对测量证明的性能问题进行优化，不以框架迁移代替问题诊断。

## 非目标

- 不迁移 React、Next.js 或其他前端框架。
- 不改变抓取任务指纹、断点恢复、论文归档、阅读状态或导入导出格式。
- 不引入 GSAP 或叙事型滚动动画。
- 不重做后端 API，不把临时筛选状态持久化。
- 不根据没有实际部署指标的 Vercel 建议重写项目。

## 方案比较

### 方案 A：密仪台

采用实验室仪器、IDE 和文献管理器式视觉，强调紧凑列表、扁平表面和快速扫描。它最适合桌面批量处理，但容易显得冷硬，并可能降低中文摘要的阅读舒适度。

### 方案 B：编辑台

采用学术编辑台式排版，突出标题、推荐理由和摘要阅读。它适合详情页与收藏阅读，但最容易滑向大留白和杂志化表达，削弱今日论文的扫描效率。

### 方案 C：语义信号工作台

保留侧栏、主结果列和右侧控制台的功能骨架，通过统一令牌、表面层级和状态语法提升品质。它与现有结构兼容性最高，也最适合分阶段落地。

采用方案 C，并吸收方案 A 的密度纪律和方案 B 的标题、摘要排版。禁止装饰性大留白、过度动画和纯灰仪器风。

## 信息层级

“今日论文”按以下五级组织：

1. 本轮任务：抓取模式、日期范围、主要操作和运行状态。
2. 结果概览：新增、已存在、待处理、失败及当前筛选摘要。
3. 论文决策信息：标题、推荐理由、作者、期刊、日期、引用和版本。
4. 状态与操作：收藏、标星、已读、LLM 重试和摘要补全。
5. 辅助控制：类型筛选、排序、热点图和历史批次。

同一时刻只突出一个推荐的抓取动作。论文标题是卡片唯一强视觉锚点，推荐理由优先于完整摘要；作者、来源和日期降低字重。颜色用于表达状态，不作为无意义装饰。

## 页面结构

桌面端保留三栏工作台：

```text
全局导航 | 抓取任务栏、结果概览、论文结果流 | 筛选、排序、热点图、条件摘要
```

- 左栏负责全局页面切换，不承载当前任务参数。
- 中栏承载本轮任务和论文决策，是页面最高层级区域。
- 右栏是辅助控制台，在对比度、表面和字重上低于论文结果流。
- 移动端将全局导航转换为顶部页面切换，右侧控制台转换为底部抽屉；关闭抽屉后保留临时选择。

## 视觉系统

- 基础色：中性灰白与炭灰作为背景和正文，青绿色只用于选中、链接和主要操作。
- 状态色：绿色表示完成，琥珀表示待处理，红色表示失败，蓝色表示处理中；浅色和暗色使用相同语义。
- 表面：统一页面背景、结果区域、论文卡和浮层四级表面，不为每个区块重复添加阴影。
- 字体：标题最强，推荐理由次之，摘要正文保持舒适，元数据和辅助说明明显弱化；减少不必要的超粗字重。
- 形状：采用统一的小圆角和细边框，避免大量漂浮式 SaaS 卡片。
- 动效：统一为 120-180ms，只服务于状态切换、筛选反馈、已读淡出和加载；尊重减少动效设置。

浅色和暗色主题必须从同一组语义令牌派生，避免继续增加主题专用选择器补丁。状态不能只靠颜色区分，还应配合图标、文字或边框。

## 组件设计

### 抓取任务栏

- “方向检索 / 指定论文”使用分段控件。
- 日期、关键词和信源集中为任务参数。
- “继续抓取 / 从头重抓 / 开始新抓取”保持真实后端语义，但只突出当前推荐动作。
- 抓取中持续显示阶段、已完成来源、失败来源和停止原因，不用短暂 Toast 代替长期任务状态。

### 结果概览

- 只显示本轮新增、已存在、待处理和失败四类决策数据。
- 概览项可形成临时筛选。
- 当前筛选条件以一行摘要显示，支持移除单项和全部清除。

### 论文卡

固定扫描顺序为：

```text
标题与引用/版本
一句推荐理由
作者、期刊、日期
论文类型与处理状态
收藏、标星、查看详情、更多操作
```

- 推荐理由默认保持可快速阅读的长度，完整摘要按需展开。
- 收藏与标星位置固定，不因字段缺失移动。
- LLM 失败、缺少完整摘要和信源失败使用不同状态。
- 已存在或已收藏论文同时使用弱化表面和明确状态文字，不能只降低整体透明度。
- 次要操作收进“更多操作”，常用的收藏与标星保持直接可见。

### 右侧控制台

- 分为筛选、排序和时间三个区域。
- 信源专属筛选只在相关结果标签下显示。
- 所有筛选立即反馈结果数，但不修改论文库、不写用户配置、不进入本地数据 ZIP。

## 数据与错误边界

视觉优化不得改变现有任务指纹、恢复按钮或 refresh state/start/status 契约。页面必须区分：

- 任务运行中；
- 单一信源分页失败；
- 单篇论文 LLM 失败；
- 未获得完整摘要；
- 整体任务失败；
- 没有结果；
- 当前筛选无匹配结果。

持续状态应保留在任务栏、结果概览或对应论文卡上；Toast 只用于短暂确认。失败提示必须给出真实后果和可执行的恢复入口。

## 可访问性与响应式

- 图标按钮必须提供 tooltip 和 `aria-label`。
- 键盘焦点顺序与视觉顺序一致，全站 `focus-visible` 清晰可见。
- 状态使用颜色与文字、图标或边框双重编码。
- 支持 `prefers-reduced-motion`。
- 在长标题、中文长词、缺失字段和窄屏下不得发生文字遮挡或横向滚动。

## 性能原则

性能阶段先建立首屏、筛选响应、DOM 数量和长任务基线，只调查有测量证据的候选：

- 独立请求是否存在不必要的串行等待；
- 重渲染是否重复绑定全局监听器；
- 长列表是否需要更严格的增量渲染；
- 筛选是否重复遍历或频繁重建 DOM；
- 非当前页面模块是否可以延迟初始化。

优化后不得让代表性数据集上的关键交互相对基线退化。没有证据的问题不进入本轮改造。

## 实施顺序

1. 冻结浅色/暗色、桌面/移动截图和 P1 工作流性能基线。
2. 建立视觉令牌，不改变功能结构。
3. 重塑今日论文任务栏、结果概览、结果流和右侧控制台。
4. 统一论文卡与状态语法，并扩展到全部论文、收藏和详情页。
5. 完善移动端、键盘、焦点、减少动效和错误反馈。
6. 处理测量证明的性能问题。
7. 分批运行测试、浏览器检查和固定端口运行态验证。

实施应拆为三个可独立验收的批次：视觉令牌与页面骨架；论文卡与状态语法；移动端、可访问性和证据支持的性能优化。

## 验收标准

- 用户可以按稳定路径完成“查看抓取状态 -> 扫描标题和推荐理由 -> 判断引用与版本 -> 收藏或标星”。
- 页面只有一个最高强调主操作，右侧控制台不与论文结果争夺视觉注意力。
- 浅色与暗色的颜色语义、表面层级和状态表达一致。
- 桌面与移动端均可访问全局导航、筛选、排序和论文主要操作。
- 收藏、标星、已读、处理中、失败和缺摘要状态可在不依赖颜色的情况下辨认。
- `1440x900`、`1280x720`、`820x1180`、`390x844` 下无不合理遮挡、溢出或横向滚动。
- 长标题、缺摘要、失败状态、抓取中和大量结果均有浏览器覆盖。
- 前后端完整测试通过；修改服务文件时在固定端口 `50751` 验证新进程时间、HTTP 200 和断点文件读写权限。
- 不改变持久化数据、配置、API Key、导入导出或备份格式，因此不需要修改 `BACKUP_FORMAT.md`。

## 风险与控制

- 中度重塑可能扩大单文件前端 diff：按三个批次实施，每批独立测试，禁止顺手重构无关逻辑。
- 令牌过细会增加维护负担：只建立被多个页面实际复用的语义令牌。
- 统一卡片可能抹平页面差异：保持字段顺序一致，但允许今日论文强调新结果、收藏页强调阅读状态、详情页强调正文阅读。
- 视觉优化可能掩盖运行问题：错误状态继续使用真实后端语义，不用统一加载动画覆盖不同失败原因。
