# 今日论文与全部论文筛选排序设计

日期：2026-07-16

## 目标

在“今日论文”和“全部论文”的右侧悬浮筛选窗中提供一致的论文分类、发表阶段和排序控制，同时保留今日论文已有的信源标签页及信源专属筛选。

## 方案选择

采用纯前端方案，直接复用论文记录已有的 `categories`、`publicationStage`、`citationCount` 和 `published` 字段。当前论文数量适合在浏览器中筛选和排序，不新增后端 API、持久化字段或依赖。

不采用以下方案：

- 后端筛选 API：会增加接口和状态同步复杂度，但不能改善当前本地数据规模下的用户体验。
- 根据标题或来源在前端重新推断分类与发表阶段：会重复后端分类规则，并产生不一致结果。

## 交互设计

两个页面的右侧悬浮窗统一增加三组控件：

1. 论文类型：偏传统算法、带有神经网络算法、偏生物结果、偏硬件创新、偏理论创新、综述。
2. 发表阶段：正式发表、预印本。
3. 排序：字段选择“引用量”或“发表日期”，方向选择“升序”或“降序”。

分类和发表阶段支持多选。同一组内为 OR，不同组以及搜索、时间、信源等既有条件之间为 AND。未选择某一筛选组时，该组不限制结果。

今日论文保留 Web of Science、Google Scholar、arXiv / bioRxiv、所有信源标签页，以及 WoS 引用量、预印本平台、版本状态等现有信源专属筛选。新增公共筛选与当前标签页和专属筛选共同生效。

全部论文保留现有抓取时间排序和时间轴。右侧选择“引用量”或“发表日期”后，以右侧排序为当前论文列表的排序规则；再次使用原有抓取时间或发表时间按钮时，切回原有时间排序。

## 日期精度

从今日论文右侧筛选定义中删除“日期精度 / 日期完整度”选项。保留论文记录中的 `publishedPrecision` 及所有日期归一化逻辑，因为它们仍用于正确表示年份、月份和完整日期。

## 排序规则

- 引用量使用有限数值参与排序。
- `null`、空字符串和非数值引用量均视为未知，无论升序或降序都排在有引用量的论文之后。
- 发表日期沿用现有日期解析规则；无法解析的日期排在可解析日期之后。
- 相同排序值保持稳定顺序，避免切换筛选时论文无故跳动。

## 状态与数据边界

筛选和排序是临时页面状态，不写入论文记录、用户配置或本地数据 ZIP。此功能不改变备份格式，不需要更新 `BACKUP_FORMAT.md`，也不产生操作日志。

## 修改范围

- `public/index.html`：筛选状态、匹配与排序函数、右侧控件和事件绑定。
- `test/paperhot_frontend.test.cjs`：覆盖控件、组合筛选、缺失引用量、日期排序和日期精度选项移除。
- `CHANGELOG.md`：记录用户可见功能和测试结果。
- `README.md`：同步设计文档索引。

不修改后端分类器、论文持久化结构、导入导出或服务 API。

## 验收标准

- 两个页面均可按全部 6 类和正式发表 / 预印本筛选。
- 同组多选为 OR，不同组与既有筛选之间为 AND。
- 两个页面均可按引用量和发表日期升序、降序排列。
- 未知引用量和无效日期在两个方向下都位于末尾。
- 今日论文的信源标签页及信源专属筛选继续工作。
- 日期精度筛选项不再显示，底层日期精度数据不变。
- 前端测试和嵌入脚本语法检查通过。
